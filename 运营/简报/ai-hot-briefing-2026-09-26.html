vLLM 支持 Gumbel-max 无失真文本水印：并进采样 kernel、投机解码用双键，吞吐基本无损失 【7.6分】

vLLM 官方博客 · 09月24日

vLLM 把文本水印做进了推理引擎本身。原理是 Gumbel-max 采样技巧：给每个候选 token 的对数概率加上一份由「密钥 + 最近 4 个 token 上下文 + token ID」经伪随机函数生成的噪声，再取最大——关键在于，这个变换在期望上不改变模型的输出分布，所以是「无失真」的：不会系统性偏向某些词、某种文风或某个解法。工程上的难点全被摊开写了：朴素实现会物化一个 [batch, 词表] 的噪声张量，显存与带宽都吃不消，vLLM 因此把伪随机数生成、Gumbel 变换与 argmax 归约融合进单个 GPU kernel（用 Philox 一次出四个值）；投机解码是最大的坑，草稿与目标分布加同一把水印会压低接受率，于是改成双键——被接受的草稿 token 用一把键、目标残差与奖励 token 用另一把，检测时两把键一起打分再合并。实测 Qwen3.5-27B 在 batch 1 到 256 的全部档位上，加水印与不加水印的吞吐曲线基本重合（八个密钥下波动在 -1.1% 到 +2.0%）；质量侧 GSM8K 93.0% vs 94.2%、MBPP 79.2% vs 77.2%、IFEval 90.7% vs 91.9%，误差棒重叠。一行 --watermark-config 即可开启，另附一个最小的 HTTP 检测服务示例。

Trump 政府用 AI 审批 Medicare 预授权：六个州试点，文件披露承包商「拒得越多赚得越多」的激励结构 【7.6分】

据 Ars Technica 报道，Trump 政府自 1 月起在六个州试点 WISeR 项目，用 AI 对部分 Medicare 服务的预授权申请做自动审批或拒批。真正被点出来的是制度层细节：EFF 公开的文件显示，承接该项目的承包商存在「拒批越多、收入越高」的激励结构——也就是说，算法不是在一个中性的目标下工作，而是在一个被设计成倾向于说「不」的激励里工作。这件事对做医疗 AI 的人有两层提醒：一是自动审批类系统的争议点通常不在模型准不准，而在目标函数是谁定的、错了由谁负责、申诉通道是否可达；二是把「效率」写进采购合同的同一份文件里，往往也写着改变行为的激励条款。它也解释了为什么各国监管对「AI 做行政决定」普遍要求保留人工复核与可解释路径——拒批率这种指标一旦和收入挂钩，模型就成了放大器。

WSO2 发布 Agent Manager 正式版：给企业 Agent 装一层「身份 + 权限 + 生命周期 + 沙箱」的独立治理层 【7.7分】

InfoQ 中文 · 09月24日

WSO2 的 Agent Manager 从 6 月 Beta 转正式版，针对的是一个正在变具体的问题：企业里能建 Agent 的模型和框架越来越多，但管理它们身份、权限、行为和生命周期的基础设施彼此割裂。它的核心主张是「治理与被治理的技术分离」——把 Agent 治理从 Agent 逻辑里抽出来，独立于底层模型、框架与运行时，换技术栈时不必重建身份、策略和监控。正式版补齐三块：可验证的 Agent 身份与授权（基于角色的访问控制、委派、token 交换、权限吊销），针对 MCP 交互的治理控制，以及 Kubernetes 原生的沙箱执行运行时；平台提供 40 多项内置控制，覆盖 PII 脱敏、速率限制等，可分别作用于 Agent、MCP 与 LLM 三层；用 OpenTelemetry 做追踪与评估，靠规则和 LLM 两类评测识别异常（token 消耗突增、行为变化、响应质量下降）。框架无关是它最大的卖点（支持 LangChain、CrewAI、Bedrock、Azure 与自研 Agent）。行业分析的一句话概括得准：现在没有单一平台能覆盖治理全栈，企业大概率得把身份系统、策略引擎、基础设施控制面与隔离运行时组合起来。

PrismAlign：华为团队给表格 OCR 装上「多视角 + 贝叶斯对齐」，TEDS 94.62、结构分 97.30，入选 EMNLP 工业轨 【7.9分】

InfoQ 中文 / EMNLP Industry Track 2026 · 09月23日

表格 OCR 的老毛病是「脑补」：面对嵌套表头、旋转扫描、无网格线的版式，单视角 VLM 会凭空补出源图里不存在的单元格、把多级表头压成一层、把模糊墨点认成货币符号——这不是偶发噪声，而是单视角视觉推理的固有盲区。华为团队的 PrismAlign 借了双目立体视觉的思路：不押注单个模型的蛮力，而是让多个 VLM 对同一版面做差异化观测，再用贝叶斯决策做一致性对齐。三个设计值得记住：把「结构对齐」与「内容对齐」解耦（前者来自几何建模偏差、后者来自 OCR 解码置信度塌缩，机理不同，度量也应不同）；把表格的几何不变量当安全护栏写进推理（行列守恒、A4 幅面的行列数上界），用「先验被破坏」与「提取出错」的相关性做贝叶斯估计；只有多视角在高置信下达成共识才落盘，其余回退为保守的低置信标记而不是放任单模型自圆其说。效果上，OmniDocBench 1.5 的 TEDS 达 94.62、TEDS-Structure 97.30，Overall 进入 95 分区间，CC-OCR 与 PureDocBench 的表格任务也达 SOTA，且不靠更大参数量或私有数据。工程侧两个落地设计很实在：单元格粒度同时输出文本与置信分，高置信自动入库、低置信只路由人工看局部 patch，人工介入面可压到原工作量的约五分之一；代码共享的部署方案避免了多模型并行时显存随模型数线性膨胀。

MM-Future：蔚来与任少卿让自动驾驶「一次推演几十种未来」，NAVSIM 拿到 94.0 PDMS 【7.2分】

量子位（ROBO 频道）/ arXiv · 09月24日

任少卿以通讯作者身份回到自动驾驶论文（上一批代表作 Faster R-CNN、ResNet 已是十多年前），第一机构为蔚来，论文《MM-Future: Multi-Mode Joint World–Action Modeling for Autonomous Driving》要解决的是一个被说清楚的空白：级联式世界模型能生成多条候选轨迹、但场景与动作只能单向传递（先决定自车通过路口，才预测到对向车没减速，这个后果已经无法回头修正前面的决策），联合式模型有双向交互、却通常只生成一组结果。MM-Future 的做法是一次生成多组「配对场景-动作假设」，每一组内部的场景与动作继续共同演化。三处工程细节：多样性靠动作端的 Gaussian Mixture Noise 加 Best-of-Many 监督（找最接近真值的一组，用同一个赢家索引同时监督动作流与场景流，避免所有候选被拉向同一答案）；计算成本靠 MM-Tokens 把多摄像头多时间帧压成面向规划的紧凑表示，不为几十种候选各生成一遍高清未来视频；筛选靠 Future-Conditioned Proposal Scorer，每个候选只读自己配对的未来（并对轨迹与未来 token 用 stop-gradient）。消融实验把每一步的贡献拆得很清楚：单模式仅生成动作 84.1 PDMS → 32 种动作候选 92.3 → 加入场景-动作联合生成、单模式 85.1、32 模式 92.9 → 评分器读取配对未来 93.3；NAVSIM-v1 上用 trainval 训练达 94.0 PDMS。代价也写明：主模型一次采样 64 组候选，单张 H800、batch size 1、bf16 下前向延迟约 233ms，16 种候选接近单模式，32 种后明显上升；MM-Tokens 属隐式表征，可解释性仍是待解问题。

蚂蚁 60 万行巨石应用 AI 重构：把目标从「迁移代码」改成「迁移行为」，并用路径证据识别「假覆盖」 【8.1分】

InfoQ 中文（QCon 上海预告） · 09月24日

支付宝生活缴费一个约 60 万行 Java、600 多个接口的核心在线系统的跨语言重构，把「AI 重构怎么算完成」这个问题逼到了台面上。演讲者蒋宇的第一句话就否掉了常见做法：代码评审通过、生成用例 PASS、覆盖率上升，都只能说明部分实现被检查过，不能证明目标业务分支真的被执行了。于是他重构的目标从「迁移代码」改成「迁移行为」，建两个相互校验的 Loop：Loop 1 回到老系统提取业务行为（PERS 建模 + Case-Forge 路径压缩 + 人机协同生成场景），Loop 2 在新系统回放相同场景、验证实际执行路径并判定差异，最后再接真实流量回放为分阶段切流提供依据。最有价值的是对「假覆盖」的复盘：实践中出现过用例描述合理、断言也 PASS，但实际执行在前置分支提前结束、目标调用根本没发生的情况——问题不在断言，而在输入、配置与 Mock 的组合没满足目标路径约束。因此有效覆盖必须同时确认目标终点是否到达、关键条件是否满足、必要调用是否发生、副作用是否符合预期，只有实际路径证据与目标一致才计入。另有三条判断同样值得抄下来：AI 可以参与场景生成，但不能独立证明自己生成的场景正确（目标定义、场景生成、执行验真必须相互独立）；老系统是行为参考而不是绝对正确的规格；离线一致不是上线的充分条件，缺路径证据、差异无法归因、没有回退能力时都不该扩大流量。

为什么值得关注

把这条当成你的验收标准升级：以后别只问「这次跑通了吗」，加一句「目标分支真的走到了吗、关键调用真的发生了吗」——实测里最容易骗过人的失败，就是用例 PASS 而目标行为根本没发生。
