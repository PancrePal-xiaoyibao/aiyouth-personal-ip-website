PhysBrain 1.5：8B 开源物理基座模型，28 项基准均分 72.5，与 GPT-6 Astra 差不到 1 分 【8.2分】

量子位 / 深度机智 · HuggingFace · 9月9日

深度机智（DeepCybo）发布物理基座模型 PhysBrain 1.5。8B 版在 28 项具身空间智能与规划基准上综合均分 72.5，居参评开源模型首位，其中 14 项开源最佳、10 项开源第二；与 GPT-6 Astra（73.3）、Gemini 3.6 Flash（73.0）的差距收窄到 1 分以内，明显拉开第二名 Hy-Embodied-VLM-1.0（66.0）与 RynnBrain 1.1（63.1）。2B 版 66.6 分，数值上超过表中所有其它开源参评模型。做法上以 Qwen3-VL-8B-Instruct 为基座扩展动作 token 与视觉状态 token，把语言回答、空间坐标、末端轨迹、未来 RGB／深度／机器人掩码全部表达为离散 token，在单一自回归主干、单一 next-token 目标下联合训练，不引入任何任务专属头，对应它提出的 Physical Loop（观察世界—理解空间与任务—判断动作后果—执行—反馈修正）。数据来自 Ego360 人类全景真实数据体系，保留全身姿态、手部运动与任务级语音；借 Human-as-Humanoid 把人类动作转成机器人动作，在 60 自由度拟人体Prime U 上验证过零样本迁移，原始示范吞吐量达传统遥操作的 4.8 至 7.2 倍。权重、技术报告、评测工具包全开源，上线 3 天下载超 3k。

为什么值得关注

值得留意的有两点。一是「一个 token 接口贯通物理循环」这个架构选择——不堆专用头，而是把理解、动作、未来预测塞进同一个 next-token 目标里；这个减法思路和你给本地小模型加专用头、专用检索、专用路由时的取舍是同构的，值得先做一次「拆掉专用模块会不会反而更好」的对照。二是 2B 版 66.6 分超过其它所有开源参评模型：具身能力的轻量档已经存在，将来给青少年做机器人或空间智能的教学 demo，消费级显卡就能跑通，不必依赖 API。分数 8.2，扣分因为是团队自评基准、上线仅三天第三方复现稀少，且 72.5 与 73.3 的差距在误差范围内，不宜当作「开源已追平闭源」的结论。

机器人重走大模型 Scaling 路：LightNav-0 跨本体零样本导航 + Light REACT 全身韧性控制 【7.8分】

机器之心 / 凤凰网科技 · 9月9日

具身智能公司亮源新创（创始人姜旭为前 OpenAI RLHF 研究者）十天内两次发布，把大模型的「规模化预训练—规模化对齐—规模化部署」三段范式往物理世界搬。9 月 1 日开源通用导航模型 LightNav-0：以 Qwen3-VL-4B-Instruct 为基座，不添加任何导航专用模块，只扩展词表——双通道指点 token 在图像坐标系里表达与任务、场景、本体无关的空间意图，RVQ 动作分词器把意图落成 10 步 SE(2) 轨迹（粗码本加两级残差，分辨率约 0.9 米／7 厘米／4 厘米），全部由基座原生的自回归语言头解码；历史观测按人类遗忘曲线压缩，采样率随帧龄指数衰减、空间池化步长指数增长，支持 256K 至 1M 三档像素预算。数据不走遥操采集，而是把 2000 余个真实场景转成仿真资产、合成 4000 余小时训练数据。同一套权重零样本部署到人形、四足、轮式乃至飞行机器人，10 项公开仿真评测领先，且仅用单目 RGB、不依赖深度与里程计，在动态跟踪基准上超过了使用全景多相机的系统。9 月 9 日的 Light REACT 解决「摔不垮」：把摔倒恢复、跛行、爬行整合进同一个 Transformer 策略，先在动力失效、关节锁死、膝折叠三类伤损域各训教师，再 DAgger 式蒸馏进单一学生，学生只接收速度指令与本体感知，伤损识别被整体推迟为对交互历史的上下文推断（全身上下文学习），参数不变、无故障标签、无模式切换。

为什么值得关注

对你的价值在于那条可迁移的建模思路：把「故障」建模成上下文推断问题而不是分类问题。Light REACT 不接收任何故障标签，只从最近的交互历史里推断「现在哪些动作还可行」——这套把状态判断交给上下文、由行为反馈反推能力边界的做法，在你做医疗或教育 agent 时同样适用：与其让用户先自报「我不懂／我不会」，不如让系统在对话里从他的实际反应推断。另外「真实世界定义分布边界、仿真负责在边界内规模化合成」这条数据路线，也是标注稀缺场景下比堆真机数据更现实的路径。分数 7.8，扣分因为成绩仍以仿真评测为主，真机验证只有演示级，且团队自 2024 年底成立、长期可靠性尚无第三方验证。

Apple researchers unveil SimpleDesign, a new AI model for protein design 【6.8分】

Apple 机器学习研究 / TMLR · 9月3日

苹果机器学习团队（Jiarui Lu、Yuyang Wang、Jiatao Gu、Navdeep Jaitly、Joshua Susskind、Miguel Ángel Bautista 等）的 SimpleDesign 已被 TMLR 接收，arXiv 编号 2609.03377。它拆掉了主流协同设计管线的两个部件：结构分词器与多阶段训练。序列端保留离散氨基酸 token 走交叉熵，结构端保留连续 Cα 坐标走流匹配回归，两套损失装进同一个多模态 Transformer 单阶段端到端训练；序列时间 t 与结构时间 t′ 独立采样，于是同一个模型可以覆盖折叠、逆折叠与序列-结构协同设计三种任务。训练数据 200 万组以上的序列-结构对，主要来自基于 AlphaFold 数据库扩充的 AFESM（约 181 万条）与 SwissProt（约 44 万条），用 64 块 H100。最反直觉的一条消融：默认用 Mixture-of-Transformer 给两个模态各配一套参数，换成普通共享参数 Transformer 后，scTM≥0.9 的自洽率反而从 74% 升到 84%。但按 scRMSD≤2Å 口径，扩散路线的 MultiFlow（0.76）与 LPROT（0.77）仍然领先，SimpleDesign 最好成绩 0.62。论文不附代码与权重，且全部结果限于计算评测，未在湿实验中验证生成的蛋白是否真的折叠、有功能、在生物体内安全。

为什么值得关注

对你的价值不在蛋白质，在那条消融结论——拆掉专用模块后反而更好。你给本地小模型加专用头、专用检索、专用路由时，值得先跑一次对照：把专用模块拿掉只留统一目标，看是不是真的更差；很多时候加分来自训练目标，而不是结构复杂度。另外「先交论文、不交权重」这个发布方式本身也值得注意，引用时别默认可复现。分数 6.8，扣分因为你不做蛋白设计，可落地性几乎为零；且计算指标未过湿实验、代码权重未公开，时效性对你也偏弱。留它是因为它是一个干净的「减法胜加法」样本。

The Qwen3.8-27B AI Model Successfully Ran On An Old Windows Laptop With 12GB RAM By Pooling Memory Of Four Devices On The Same Network Using Open-Source Software 【7.5分】

wccftech / Reddit r/LocalLLaMA · 9月10日

Reddit 用户 Medicine_Blogscanner 用开源工具 RAMDeck，把一台只有 12GB 内存的旧 Windows 笔记本（主节点，分配 3.4GB）、一台 RTX 3060 迷你主机（约 20GB 显存加内存）、一台 Mac mini（3.7GB）和一台安卓手机（1GB）拼成约 28GB，成功加载并运行 4bit 量化的 Qwen3.8-27B（4bit 需 15 至 17GB，未量化版本要 55 至 60GB）。代价同样直白：生成速度只有 1.92 tokens/秒、延迟约 25 毫秒，同一作者此前用同样方式跑过 7B 与 13B，模型越大速度衰减越明显。RAMDeck Core 用 llama.cpp 的 RPC 协议跨设备卸载张量，每台设备跑一个节点程序提供 GPU 或 CPU 资源，再由协调器调度；仓库自述「能跑但不完美」，没有图形界面与完整仪表盘，安装要配 Python 环境、起节点 agent、自备兼容的 llama.cpp 工具或协调器，上手门槛不低。许可证是 Apache 2.0 加 Commons Clause（限制商用转售），严格说不算 OSI 认证的开源。

为什么值得关注

这条对你的直接价值是「内存不够可以有解，但带宽不够没解」这个物理约束。它把容量问题解决了（几台吃灰设备凑出 28GB），却把带宽问题暴露得很彻底：张量要走局域网 RPC 交换，1.92 tokens/秒基本只能做技术验证。所以判断依据是——如果你要跑的是批量、离线、不赶时间的任务（比如夜间批量打标签、长文档摘要），分布式拼内存是划算的；如果是对话或交互式 agent，别碰，宁可上 2bit 量化或小一档的模型。顺带记一个事实：NVIDIA 的 RTX Spark 平台正在往 128GB 统一内存走，说明业界的解法也是「把内存搬到离算力更近的地方」而不是跨机器分摊。分数 7.5，扣分因为它是单人的技术演示、无基准复现，且 Commons Clause 对商用有限制。

OpenAI放大招，一句话生成网站革了SaaS的命！ 【7.7分】

新智元 / Fast Company · 9月12日

OpenAI 的 ChatGPT Sites 进入公测，向 ChatGPT Plus、Pro、Business、Enterprise 与 Edu 用户开放。流程是：几句话描述想要的网站类型与目标受众 → 上传喜欢的网页截图或手绘草图 → 提出功能要求（链接按钮、嵌入式视觉效果、复杂交互）→ 等 10 到 15 分钟，产出完整可交互网站。早期测试者做出的东西包括媒体赞助页、旧金山活动指南、支持把商品拖进购物篮的在线商店，以及涉及流体物理引擎的艺术工具GoalFlow、带真实物理效果的叠叠乐游戏 Glass Towers。迭代方式是侧边栏的注释工具：像批改作业一样在网页上圈一块，说「把这个按钮颜色改了」「字体换无衬线」「替换这张图」，它直接改。真正的差异不在生成质量而在生态位——如果工作在 ChatGPT Project 里，它会自动读取品牌风格指南与 Logo 库，生成的站点天然带品牌一致性。同期流传的还有一组跨模态测试：GPT-6 Astra 仅凭一张 Mel 频谱图、在无音频播放且离线的条件下，零样本识别出蓝鲸叫声与《星球大战》的光剑音效，提示词只有一句「这是自然界某种动物的声音」。

为什么值得关注

对你最直接的用法不是建站，而是那个「圈选局部 → 自然语言改」的迭代范式：它把「改一个具体位置」从描述坐标、找选择器、说行号，变成了在成品上直接指。你给客户做交付物（课件、页面、报告）时，如果能在产物上提供一个可直接圈的入口，返工沟通成本会断崖式下降，这比再提升一次生成质量更值钱。另一个该警惕的点是端到端生成对中间层工具的挤压：凡是只做「让非程序员更容易写代码／建站」的过渡型产品，都会首当其冲——如果你手上有这类定位的东西，现在就该重估。分数 7.7，扣分因为它是公测期的演示性案例，没有成功率、可维护性、导出与托管等硬指标，且「革了 SaaS 的命」是媒体口径而非已发生的事实。

Cognition helps Devin test its own work with GPT‑6 Astra 【8.0分】

OpenAI 官方 · 9月11日

OpenAI 发布的客户案例：Cognition 让 Devin 用 GPT-6 Astra 做的主要不是写代码，而是测试并证明自己写的能跑。联合创始人 Walden Yan 的说法是，Astra 最大的改进在于「测试并证明它的工作确实按你预期运转」的能力。一个具体例子：Devin 用 Astra 测 iPhone 游戏 Otter Run，返回的是模拟器里游戏运行的录屏，加一份「哪些检查通过、哪些区域未覆盖」的报告——录屏展示行为，报告说明测试边界，工程师据此判断还剩什么要看。客服侧则是：客户发来 bug 截图 → 交给 Devin → 修复后返回一张修复后的截图。能力铺在 Devin 云 agent、CLI 与桌面三条产品线。目标被表述为「随着时间的推移，我们需要人工看的代码越来越少，最终交付更多」。需要说明的是，这是 OpenAI 发布的客户案例稿，通篇定性描述，没有准确率、缺陷率或成本方面的量化指标，也没有第三方验证。

为什么值得关注

这条值得你细看的原因不是「AI 会自测了」，而是它把评审的对象从代码换成了证据：录屏 + 通过项 + 未覆盖项，人类判断的是「这段证据够不够」，而不是逐行读 diff。你在给客户做 agent 交付时可以直接套这套输出格式——让 agent 每次交付都附「我做了什么、我验证了什么、哪些我没验证」，把未覆盖区域显式写出来；这比承诺「已全面测试」诚实，也更容易过验收。但要同时记住它的盲区：代码由写它的同一个角色测，不会在屏幕上暴露的缺陷（数据错、权限错、合规错）它测不出来，所以证据不能替代独立验证。分数 8.0，扣分因为没有量化数据、是厂商案例，且「未覆盖区域」由模型自己列，本身就可能有遗漏。

从沙箱到执行边界：蚂蚁 AI Agent 的大规模企业级实践｜QCon上海 【8.3分】

InfoQ 中文 / QCon 上海 2026 · 9月12日

蚂蚁集团高级技术专家林鑫在 QCon 上海（10 月 22 至 24 日）的议题《从沙箱到执行边界：蚂蚁 AI Agent 的大规模企业级实践》提前披露了 ARCA 执行边界体系。他先列了企业级 agent 的五难：隔离难（既要放开执行能力，又要守住租户、身份、网络和内核边界）、启动慢（安全容器、镜像拉取、依赖初始化与持久化挂载叠加后的冷启动）、状态重（办公、Coding、长任务 agent 需要保留 workspace、依赖、会话与执行上下文，但资源不能长期空转）、规模大（Agentic RL 与批量评测会带来镜像风暴、缓存击穿、多集群调度与配额竞争）、治理散（哪些高危动作何时进沙箱、进沙箱后如何共享状态与注入审计，不能靠业务代码临时判断）。三类场景里沙箱扮演三种角色：Sandboxed Agent 中它是 Agent 的家（Piston 管模板与生命周期，ARCA Sandbox 管安全容器、缓存池、持久化、内存快照、镜像预热、网络隔离与成本治理）；Agentic RL 中它是环境供应链（镜像懒加载、缓存感知调度、多集群路由、失败重试）；Harness + Tool Use 中它是危险动作执行器（Tool Gateway 与运行时策略按 actiontaxonomy 与 risk metadata 做 policy-before-dispatch，决定 host 执行／dry-run／人工审批／沙箱执行／拒绝）。规模：支撑数万级每日沙箱创建、千万级日请求、万核级资源峰值。

为什么值得关注

「沙箱有三种角色」这个分类是你今天最该带走的框架，因为它直接否定了一种常见做法——把所有东西都塞进沙箱。正确问法是：Agent 自主性在哪、风险动作在哪、状态在哪、身份在哪、成本在哪，按答案决定沙箱是「家」「供应链」还是「执行器」。你给客户设计 agent 时，最常见的失败是只做了容器隔离，却没定义哪些高危动作必须走审批——他的 policy-before-dispatch 是一个可直接抄的最小实现。另一条实用经验是「先定义执行边界，再优化启动性能；先拆状态，再谈弹性；先平台化策略，再放开 Tool Use」这个顺序，一人公司做自动化时也适用：先把不可逆动作列出来分级，再谈提速。分数 8.3，扣分因为这是会议议题预告，详细实现要等 10 月现场，可复现性暂时为零；规模数据也由蚂蚁自报。

大模型全是演技派！AI教学的正确方式：用真实数据训出60个数字学生 【8.1分】

新智元 / Microsoft Research · arXiv · 9月12日

微软研究院与伊利诺伊大学厄巴纳-香槟分校提出 StudentSim（arXiv 2609.01591，代码在 github.com/microsoft/StudentSim）：用真实学生记录训练可评估、可复用的 AI 学生，解决 AI 教师需要个性化反馈、但 human study 采集慢且贵的问题。方法分两步——先在领域内多名学生的 pooled 记录上训练通用学生行为模型（学共性错误、回答格式、接受指导后的修正路径），再用单个学生自己的记录继续训练出个性化模拟器（缓解单人数据稀疏导致的过拟合）。评估定义两个维度：behavioral fidelity（独立作答时像不像这个学生）与 guidance responsiveness（读到教师指导后会不会相应改变），覆盖国际象棋、二语英语写作与基础数学三个场景共 60 位真实学生。国际象棋上 StudentSim 的 F=0.5150、R=0.9067，GPT-5.4 为 0.2316 与 0.7186，Maia2 为 0.4535 与 0.2721。把 StudentSim 接进 AI tutor 的 GRPO 流程后，盲评中准确性、指导质量与个性化三项均第一；反直觉的是用 GPT-5.4 当学生模拟器训出来的 tutor，准确性不仅输给 StudentSim，还低于完全没做 RL 的基线——因为不保真的模拟器读完再离谱的指导也能自己推出答案，等于给错误指导发了随机奖励，RL 就朝着混乱的方向优化。

为什么值得关注

这是今天与你受众关联最强的一条，建议你直接做成一期内容。它给出了一个能反驳直觉的结论：让大模型「扮演一个数学不好的小学生」是无效的——它可以用小学生的口吻说我不懂，下一句却给出微积分级别的推理；用这种模拟器当奖励信号，会把老师越训越差（实验中甚至不如不做 RL）。这正好回答家长最常问的那句「AI 能不能辅导我家孩子」：能，但前提是它有这个孩子真实的学习记录，而不是一句人设提示词。可落地的动作是：如果你要做教育类 agent，把「采集真实错误样本」当成第一等工程任务，而不是把调提示词当第一等任务。分数 8.1，扣分因为它目前只在三个结构化程度高的场景验证，真实课堂的开放性远超这些场景，且 60 人的样本规模有限。

It's All Fun and Games Until You Give AI Your Credit Card 【8.3分】

The Atlantic · 9月12日

《大西洋月刊》记者 Lila Shroff 实测把信用卡与数字账户交给 AI 助理 Instinct 之后的真实翻车。一位用户的航班在展示取消费用之前就被取消了，bot 事后自述：「在调取取消条款时，取消操作实际上在我能先把费用给你看之前就已经生效了。」一位洛杉矶男子只让 bot 扫描餐厅预订，bot 却在未获批准下订了一家含 200 美元取消费的餐厅。另一位想订西村一家牛排馆，bot 不知情地向 Resy 狂发请求，导致他的账号被临时封禁。隐私侧同样失控：让 bot 代回朋友的日程短信，可能顺带泄露「周四上午有离婚律师预约」这类信息。作者自己测试时，bot 在代发 Craigslist 取货消息时被验证码难住，自嘲被「九条模糊的斑马线」击败。Instinct 的隐私政策写着：没有任何安全措施是不可穿透的，我们无法保证完美安全。作者的做法是隔离测试——临时手机号、不连主邮箱、只用一张计划用完即停的虚拟卡，结束后立刻删号。

为什么值得关注

这条和今天 Devin「自证」那条是一体两面：一个在解决「怎么证明 AI 做对了」，一个在提醒「做错了就是真金白银的损失」。两点建议你今天就执行：一是把隔离测试做成规矩——任何持有支付或账户权限的 agent，一律临时号 + 一次性虚拟卡 + 不连主邮箱，跑一遍取消、下单、退款这类不可逆动作，看它在哪一步会先斩后奏；二是把「先展示代价再执行」写进你自己的 agent 设计约束里，这条 Instinct 的翻车恰好证明了它不能靠模型自觉。对内容侧也有用：面向家长讲「为什么不能把支付权限交给 AI」时，200 美元取消费和被封号这两个例子比任何风险论述都直观。分数 8.3，扣分因为文章是单人体验式报道、样本是个案，不构成对 Instinct 的系统性评测。

怒斥加密货币是旁氏骗局、放弃80%就业机会也不用 AI 写代码！Kotlin“J神”：AI 会让工程师变成可替换的齿轮 【8.0分】

InfoQ 中文 · 9月12日

Jake Wharton（Android 与 Kotlin 社区知名开发者）找新工作时列了九条择业标准，第一条是「不加入 AI 公司、不做以 AI 为核心的产品、不接受强制使用 AI 开发」，第二条是「不加入加密货币公司」——仅第一条就排除了约 80% 的潜在雇主，最终他加入了符合标准的 Skylight。他的论据有四条值得单独看：一是版权与许可，网上可访问不等于拥有改写或逐字输出的权利，LLM 建立在大规模使用受版权保护内容之上；二是依赖导致失控，如果离开大模型就完不成任务，说明你并没有真正理解结果，一旦模型涨价 20 倍、公司只买得起 4% 的 token，工程师会突然丧失工作能力；三是经济账，LLM 目前由资本补贴，先用低价养出依赖再按实际价值收费，成本可能涨 1 到 2 个数量级，当 AI 成本超过被替代工程师的薪酬，替代模式的经济逻辑就失效了；四是强制推广的方向错了——过去新语言与 IDE 由工程师发现价值后自下而上推广，现在是 CEO 自上而下强推。他把结果概括为：交出去的不只是部分工作，还有自己的能力和议价权，最终「变成一枚更容易被低成本替换的齿轮」。他对加密货币的判断是「基本上已经变成一种庞氏骗局」，但强调密码学本身是有价值的技术。

为什么值得关注

我知道这条的立场与你的日常相反，正因为相反才值得读。最该拿走的是第三条经济账：当前 token 价格是补贴价，按历史规律补贴退坡时成本可能涨一到两个数量级——你给客户做三年期方案时，如果不做这个敏感性测算，第二年的账单会直接击穿报价。第二点是他说的「依赖导致失控」：判断标准很简单，如果离开 AI 你做不成这件事，那这件事就不该由你签字交付，这在医疗场景里尤其成立。至于他整体拒绝 AI 的立场，我不同意——他把「用 AI 增强已有能力」和「让 AI 生成自己看不懂的东西」分开讨论时是对的，但他拒绝的是后者却连前者一起拒了；你讲课时可以用这个区分去回应他，比单纯站队有说服力。分数 8.0，扣分因为他的论据里关于成本的部分是推演而非数据。

今日行动建议

  1. 照着今天上下文工程那篇给自己的长任务 agent 加两级卸载：工具返回超过 20000 token 就写文件、只回路径与前 10 行预览；会话上下文越过窗口 85% 时把旧的 write/edit 调用截断成指针。顺手把持久规则文件压到 200 行以内——ETH 的数据说它不提升成功率，却会让推理成本涨 20% 以上，这是每轮都要付的注意力税。
  2. 量一笔双份账：凡是会把前文重新塞给大模型的环节（重试、续写、重新规划），之前生成的 token 都会被计费两次——一次按小模型输出，一次作为大模型的输入 prefill。今天先找出你管线里最贵的一处，再决定要不要上「小模型先化简、大模型只收尾」的分层结构。
  3. 给任何持有支付或账户权限的 agent 做一次隔离测试：临时手机号、一次性虚拟卡、不连主邮箱，跑一遍取消、下单、退款这类不可逆动作，记录它在哪一步会先斩后奏。Instinct 那 200 美元取消费的教训是——「先展示代价再执行」不能靠模型自觉，得写进约束里。
