OpenAI 发布 GPT-6 Astra：1.05M 上下文的计算机操作模型，因触及 Critical 网络安全阈值而限制访问 【8.0分】

MarkTechPost（RSS） · 9月4日 05:16

OpenAI 把 Astra 定位成「计算机操作模型」而非聊天模型：1,050,000 token 上下文、128K 最大输出，OSWorld V2-Offline 得 72.6%（GPT-5.6 Sol 为 65.7%），平均任务耗时从约 75 分钟降到 40 分钟；官方还给出 ARC-AGI-3 99.9%、FrontierMath Tier 4 97.6%、Terminal-Bench Science 64.6%（Anthropic 报 52.6%）。编码反而是短板——DeepSWE v1.1 仅 74.1%，对比 Sol 的 72.7% 只差一两个任务。它同时是 OpenAI 首个触及 Preparedness Framework「Critical」网络安全阈值的模型：测试中为加固过的浏览器与操作系统写出了可用漏洞利用，并发现两个未知 V8 漏洞，因此目前只对 Trusted Access 与 Daybreak 计划内的机构开放，普通 API 遇到高级网络安全任务会被直接拦下。定价 $10/$50 每百万 token，超过 272K 输入按 2 倍计费。

为什么值得关注

Give Your Coding Agents a Memory You Own 【9.0分】

HuggingFace Blog · 9月3日（HF 博客）

Hugging Face 开源 funes：给编码智能体的持久记忆层，single binary，支持 Claude Code、Codex、pi、Hermes。核心主张是「记忆是一个数据集，而不是一项服务」——把本机已有的 agent 会话轨迹解析成统一的 turn-and-block 结构，本地完成 embedding 与 rerank（向量 + BM25 混合，再过 cross-encoder 与近期性重排），存为本地 Lance 数据集；写入时不蒸馏、不总结，recall 返回原始文本并带 agent／时间戳／会话／turn 溯源。一条 `funes add <agent>` 完成建索引、装 recall 与 get 工具、配置每个 turn 后的增量索引；绑到 HF dataset（默认私有）即可跨机器同步。官方基准中 recall 比手写 handoff 便宜 4~8 倍，而 compaction 会把关键发现压平、甚至导致任务永不收敛。

为什么值得关注

这条几乎是照着你现在的痛点做的：Hermes 和 Claude Code 都在支持列表里，本地优先、不依赖托管模型处理你的会话，索引时脱敏、发布前再扫一遍密钥。最值得抄的是「不蒸馏、返回原文 + 溯源」这条设计——对比你一直担心的 compaction 丢细节问题，funes 给的答案是把证据留全。装上之后跨 agent 记忆是通的，从 Claude Code 换到 Codex 不再从零开始。

Empty shelves or lost keys? Recall is the bottleneck for parametric factuality 【8.3分】

Google Research · 8月12日（Google Research 博客）

Google Research 提出「知识画像」框架并构建 WikiProfile 基准（2150 条维基事实、每事实 10 个任务、13 个模型、约 450 万条响应），把事实性错误拆成「空书架」（从未学会）与「丢钥匙」（学会了但想不起来）两类。结论是前沿模型的事实性瓶颈已从编码转向回忆：Gemini-3-Pro 与 GPT-5 编码了 95%~98% 的事实，但仍有 26%~34% 无法直接回忆，即使开启 thinking 也有 11%~12% 失败。thinking 能恢复 40%~65% 的「已编码但想不起来」的事实，对未编码事实只恢复 5%~15%。所谓反转诅咒（知道 A 是 B 却答不出 B 是什么）在多选题验证中并不存在，是纯粹的回忆问题。

为什么值得关注

这条直接改写知识库问答的优先级：别再指望靠加数据、堆 RAG 来解决幻觉——事实大概率已经在参数里了，问题在取不出来。两个可落地动作：一是对稀有事实与反向提问强制走 thinking（收益最大的两处），二是把「生成失败」改成「先生成 + 再多项选择验证」，把可识别但不可生成的事实捞回来。给医院做的知识库如果还在靠加文档压幻觉，值得照这条重算一遍投入产出。

BenchMIRT: What are LLM benchmarks actually measuring? 【7.3分】

HuggingFace Blog · 近日（HF / Ai2 博客）

Ai2 发布 BenchMIRT，用心理测量学的多维项目反应理论（MIRT），在 100 个模型、16 个基准、超过 3.4 万道题上，把 LLM 基准审计下沉到单道题的粒度；它无监督地恢复了两个主导能力维度——安全与通用推理。结果发现不少基准在混测：BBQ（社会偏见）与 WMDP（危险知识）的分数与通用推理的相关性强于安全性，HarmBench 的版权题更接近推理而非安全，WildJailbreak 把有害提示与无害提示平均成一个分数、掩盖了两者分属不同维度。另一结论是大量题目冗余：只保留 10% 的高区分度题目，就足以还原模型在安全或推理上的强弱排序。

为什么值得关注

「基准分数高」不等于「能力强」的老问题，第一次有了能照着做的量化工具。可以拿它反过来审视自己汇报时引用的那些榜单：如果留 10% 的题排序都不变，那剩下 90% 的评测成本基本是白烧的。对做量表 AI 平台也有直接启发——题目区分度是可以估出来的，不是拍脑袋定的。

Gary Marcus 评 GPT-6 Astra：进步明显但鲁棒性与可监控性存疑 【7.3分】

Why office workers are turning against AI 【7.3分】
