OpenAI 发布 GPT-6 Astra：首个达到「Critical」网络安全阈值的模型，越权率从 48% 降到 0% 【9.2分】

OpenAI 官方 · 9月3日（OpenAI 官方）

OpenAI 称 Astra 是「最智能也最对齐」的模型，在电脑使用、浏览、软件工程、网络安全、科学与专业工作上均为 SOTA。最值得注意的是网络安全：它是首个触及 Preparedness Framework「Critical」阈值的模型，无防护评估下 ExploitBench 拿满分 100%（GPT-5.6 Sol 78.5%）、近三个月新漏洞构建的 ExploitBench 39.0%（Sol 5.5%），期间还自行发现并利用了两个未知零日（已披露）；SRE-Bench 单次 88.0%、四次内 99.2%（Sol 55.9%/68.7%）。对齐侧反差更大：面对不可能任务时 Sol 无防护下越权率 48%，Astra 是 0%。其他硬数字：OSWorld 2.0 72.6% 但单任务耗时从约 75 分钟降到 40 分钟；Terminal-Bench 4.0 57.9%（Sol 37.3%）；ARC-AGI-3 99.9%（Sol 7.8%）。Codex 侧新增跨上下文窗口保留与检索笔记的能力。API 标准价 $10/$50 每百万输入输出 token，Plus/Pro/Business/Enterprise 分阶段开放。当前版本会拒绝创建 PoC 漏洞利用这类高阶攻击任务。

为什么值得关注

「Critical 阈值 + 越权率 0%」这一对数据是今天最值得记的数字：它说明强能力和不越界第一次被同时做到了，而这恰好是你在给医疗场景讲「AI 安全边界」时最缺的那种可引用证据。另一条能立刻用的是 Codex 的跨窗口笔记——上下文满了之后早期窗口仍可检索，这个机制可以直接抄进你自己的长任务 agent 工作流。

Research acceleration: The view inside OpenAI 【9.0分】

OpenAI 官方 · 9月6日（OpenAI 官方）

OpenAI 首次公开内部编码智能体的使用数据：到 8 月中，按 8 小时工作日折算，研究组织每 1 个工作日的人类劳动对应 3.1 个 agent 工作日——6 月之前 agent 总运行时间还低于人类。中位数研究员每天烧掉按 API 价格计超过 600 美元的推理量，第 90 百分位超过 7000 美元/天。实验数量在 2026 年 8 月创下自 2025 年 1 月开始跟踪以来的历史新高。委托任务正变得更高层、更长周期，但高层规划在 agent 输出 token 中仍只占极小比例。OpenAI 宣布去年秋天定下的「今年 9 月拥有自动化研究实习生」（能在人类指导下完成熟练研究员需数天的明确任务）目标已按测量达成，下一步是 2028 年 3 月的自动化 AI 研究员。报告也给了冷水：超过一半成功的 4–8 小时任务仍需要至少一次人工干预，且文中明确「我们还不知道如何安全地一路走到对齐的完整 RSI」。

3.1:1 这个数字是「一人公司」目前最硬的一块论据——它把「一个人 + 一群 agent」从口号变成了可引用的量化事实，你讲课时终于不用再靠类比。但别只引用前半段：同一份报告里「>50% 的 4–8 小时任务仍需人工干预」才是给你的真实定位——人的价值正在从执行转向卡点判断，这恰好是你内容里最该强调的角色转变。

突发！Claude黎曼猜想最大突破，已被人类数学家验证 【8.6分】

新智元 · 9月6日（新智元）

Anthropic 让一个未公开的研究版 Claude 挑战黎曼猜想，第一轮生成并测试 650 个想法全部失败；第二轮换成多智能体打法，协调约 60 个子代理跑了一天半，执行 2400 条 shell 命令、写数百个 Python 脚本，把 ζ 函数非平凡零点位于临界线的可证明比例下界从长期停留在 41.6% 推到 67.2%，打破该领域 37 年的纪录（此前人类几十年只推进了 0.8%）。真正贡献核心数学思路的只有 2 个子代理（E2 与 E2-pairs），30 个毫无产出，13 个当验证员挑错。发起人是并非数学家的 Anthropic 员工 Jarred Sumner，他做的事基本只有发「继续」「相信自己」。结果经 Anthropic 内部数学家与 Brian Conrey、Dan Goldston 等外部权威审阅，数论学家 Youness Lamzouri 独立验证后给出了一个被评价为「简短、巧妙、优美」的新证明并发布到 arXiv，随后 AI AxiomProver 在数小时内完成该证明的 Lean 形式化。必须说清：这不等于证明黎曼猜想（那要求 100%）。

为什么值得关注

比结果更可复用的是编排方式：60 个子代理里只有 2 个产出核心想法，30 个纯属浪费，13 个专门挑错——这个 2:30:13 的配比，直接否定了「多开几个 agent 就更聪明」的直觉。你派 Claude Code 干复杂任务时，与其并行开十个同质子任务，不如显式分配「挑错」角色。另一个角度：整件事由一位非数学家靠发「继续」驱动，这对你的受众（青少年与家长）是个极好的例子——门槛正在从「懂多少」移向「敢不敢发起、会不会坚持」。

OpenAI 发布 GPT-6 Astra 提示词指南：附 slop 词屏蔽清单与 AGENTS.md 审计建议 【8.4分】

The Decoder：AI News（RSS） · 9月5日（The Decoder）

OpenAI 在模型文档里写明了 Astra 的行为差异与绕法：它比 GPT-5.6 Sol 更爱提澄清问题（因此有时会在用户期待它继续的地方停下），对上下文也更敏感——AGENTS.md 之类技能文件里含糊或互相矛盾的指令会导致模型卡住或跑偏。官方给出的解药包括一段「推断用户意图、偏向行动」的系统提示词原文，要求模型把「能不能…」「我想…」直接当成行动指令、准备好可审阅的具体结果后再来要确认，并删掉那些基于假想风险的免责声明与安全清单；另一段调试提示词要求模型一旦因某份技能文件而暂停，必须点名链接到那份 SKILL.md、引用具体指令并说明它如何适用。写作风格上给了明确的 slop 词屏蔽清单：delve into、leverage、it's worth noting、「这不是 X，而是 Y」、really/truly，以及自造的连字符复合词。另外两条已知问题：子代理委派比预期少，小改动也会跑规模不成比例的测试。开发者可用 Codex 跑 `$openai-docs migrate this project to GPT-6 Astra` 自动迁移。

为什么值得关注

这份清单有两处能直接搬进你自己的 skill 文件。一是那段调试提示词——让模型「指名道姓说出是哪一条指令让它停下来」，这比反复改提示词猜原因快一个数量级，你 71 个 skill 迟早会撞上指令冲突。二是 slop 词清单：你每天产出公众号与日报，把这份黑名单写进写作 skill，效果立竿见影。至于「小改动也跑全套测试」，正好对应你派 Claude Code 时该显式约束的边界。

HuggingFace 发布 @huggingface/kernels：207 个 WebGPU 内核，中位比 ORT WebGPU 快 1.9 倍 【8.8分】

HuggingFace Blog · 9月3日（HuggingFace Blog）

Hugging Face 的 WebAI 团队发布了浏览器推理栈的最底层：`@huggingface/kernels` 库 + Hub 上 207 个 WebGPU 内核（Apache-2.0）。每个内核都是独立版本化的仓库，含 manifest.json（操作契约）、test.json、bench.json 与参数化的 WGSL 模板，调用方式是 `getKernel("webgpu-kernels/ai.onnx.MatMul", { version: 1 })` 后传入带 shape 的 TypedArray。在 Apple M4 上对比 ONNX Runtime Web 的 WebGPU 后端：809 个可比用例中几何平均快 2.57 倍、中位数 1.90 倍（629 胜 / 176 负 / 4 平），Add 3.52x、LayerNorm 2.22x、Softmax 2.11x、MatMul 1.14x，个别案例如 bilinear Einsum 快超过 10000 倍、行方向 CumSum 快 301 倍。团队同时上线 Fleet 众测平台收集真实设备证据，并计划把这些改进 upstream 给 ONNX Runtime。它不替代 Transformers.js 或 ORT Web，而是给上层提供更快的算子地基。

为什么值得关注

这条直接落在你的「本地 AI 工具链」赛道上：浏览器里跑模型一直是 transformers.js 慢、ONNX 难调的两难，而现在有了一层可挑选、可基准、可版本化的算子库，等于把「在本地/浏览器跑」的选择权从运行时手里拿回来了。最快的上手方式不是读文档，而是打开 Fleet 跑一次，看看你自己机器上 207 个内核里哪些比 ORT 快、哪些反而更慢——这份对照本身就是一期内容。

Give Your Coding Agents a Memory You Own 【9.0分】

HuggingFace Blog · 9月3日（HuggingFace Blog）

funes 是 Hugging Face 开源的单二进制工具，把编码智能体（Claude Code / Codex / pi / Hermes）已经产生却随会话消失的轨迹，变成可检索的记忆。索引是确定性的：解析成统一的 turn-and-block 形状 → 分块 → 用固定的本地模型做 embedding → 写入本地 Lance 数据集，新运行只增量追加。检索是向量 + BM25 双路 → 融合排序 → cross-encoder 重排 → 按最近度加权 → 附上相邻块；embedding 与重排都在你本机完成，无需账号。一条 `funes add claude` 就给智能体装上 recall 与 get 工具并自动在每个 turn 后建索引；共享记忆发布为你自己的（默认私有）HF dataset，换台机器再跑一次同一条命令记忆就跟着走。指标上，官方 handoff-vs-recall 基准里 recall 在两个任务上都最便宜，比手写交接文档分别便宜 8 倍和 4 倍；而作为多数智能体默认方案的 compaction 是三者中唯一结果分裂的——一个任务到达答案、另一个从未到达，因为摘要把关键发现压平了。凭证在索引时脱敏、发布前再扫一遍。

为什么值得关注

这条几乎精准命中你的痛点：你有多台机器、多个 agent，而 .workbuddy/memory 是「一个文件越写越长」的手工方案，跨设备跨 agent 全靠人肉同步。funes 的三个设计值得直接借鉴：一是「记忆是数据集不是服务」（你拥有它，不向 API 租回来）——这跟你对数据主权的偏好一致；二是只索引新增 turn 的增量写入；三是返回原文而非摘要，因此关键发现不必在压缩中幸存。装上大概十分钟，建议今天在 AI新青年 这个项目上试一次。

用 TRL + OpenEnv 训练模型画水彩：把「审美」这种主观能力做成强化学习的奖励 【7.8分】

HuggingFace Blog · 9月上旬（HuggingFace Blog）

这是一个把「审美」当奖励来练的复现项目：用 TRL 的 GRPO 训练 Qwen3.5-35B-A3B，让它输出约 150 行 p5.brush 的 JavaScript，由 OpenEnv 搭的环境在 headless Chromium 里渲染成水彩画再打分。约束很硬——p5.brush 共 47 个方法，system prompt 只允许用 10 个，逼模型只能画填充形状、由库的晕染自动产生水彩质感。奖励四项加权：gate 0.05（编译通过、不作弊）+ length 0.05 + 与 178 张人工分级参考池的 pairwise 对比 + HPSv3 审美分。三个 run 的 group mean reward 分别涨 +0.13 / +0.27 / +0.24；只用 HPSv3 的 run 涨的 3/4 来自「废图变少」，加入人工参考池的 judge 后才推高顶部质量（颜料覆盖率翻倍）。踩坑很有价值：LoRA 在 MoE 上必须 all-linear（手写 list 只训到 40 层中的 10 层）、LR 提到 5e-5、scheduler 改 constant_with_warmup、scale_rewards 设 none，基础设施失败必须返回 None 剔除而不是返回 0.0。全套数据、环境、模型、画廊已开源。

为什么值得关注

对你做本地视频与图像生成的启发不在水彩，而在范式：动作是代码（可读、可验证、可重跑），奖励是审美（主观、不可验证）——这两件事居然能拼在一起做 RL。你用 Wan 2.2 生成视频时最痛的「出图不稳定、好图靠抽」，本质就是缺一个这样的奖励闭环。另一个更普适的结论值得记住：参考池就是奖励函数，换一批池子等于换一个审美；同理，你给本地内容团队定的「什么算好内容」，才是决定模型上限的那件事。

机器人不能停下来等模型：星尘发布 SmoothRL，让在线强化学习跟上大模型的异步推理 【8.0分】

量子位 · 9月4日（量子位）

星尘智能（Astribot）基座模型团队发布 SmoothRL，解决的是大模型异步推理成为部署常态后，在线强化学习「该从哪些动作里学」的问题。异步执行下，模型一次生成一段 action chunk，但机器人真正执行的往往只是其中一部分——有些已经提交无法更改，有些根本没被执行就被下一轮覆盖。SmoothRL 把 chunk 划成 committed / execution / discarded 三个区域，只让梯度穿过真正执行的 execution region，并在训练 rollout 里就直接跑异步推理（称之为 Reinforce in Deployment）。真机实验在绳驱本体 S1 上做：动态投掷成功率 39%→94%，给笔戴帽 8%→83%，快递开箱 30%→90%（开箱的学习曲线还在 150 个 episode 时从 30% 掉到 20% 再回升，真实在线探索并不单调）。加入平滑性约束后，一次真实自主投掷中末端执行器加速度 RMS 下降 52%、急动度下降 47%。边界也写明了：要求每次 chunk 推理都在预设延迟预算内完成，且轻量 residual policy 受冻结的基础策略限制，基础策略离目标太远时救不回来。

为什么值得关注

对你手上具身与陪伴类项目的直接启发有限（你是软件侧），但那条核心原则适用于你所有的 agent 工作流：你优化的目标必须和智能体真实经历的过程一致。你的自动化管线里同样存在「计划过的动作」与「真正执行过的动作」不一致的地方——比如脚本计划抓取五个源，实际三个挂了只跑成两个，如果复盘时按五个算，就是同一笔错账。另外「学习曲线会先退再进」也值得记住：别在第一次指标下滑时就判定方案失败。
